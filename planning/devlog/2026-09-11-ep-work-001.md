# Devlog — 2026-09-11 — EP-WORK-001 human-work queue read endpoints

## What landed

`WorkService`'s two read procedures now exist end to end:

- `internal/humanwork/workitem/view.go` — the read rules the endpoints
  apply: membership (live claimant > assignee > surviving candidate),
  visibility classification (assignee-only, candidate set, organization
  scope, tenant governance), evidence gating, and the permitted-action
  set derived from the same lifecycle edges the store enforces on write.
- `Store.ListQueue` — the durable queue read: live items the principal
  may act on, deadline/id ordered, inside `tenant_isolation` RLS.
- `internal/intent/app.WorkItemQueueReader` — the application port the
  transports read through (reads run in tenant-scoped, always-rolled-back
  transactions).
- `internal/transport/humanwork` — the gRPC + Connect surface. Cursors are
  HMAC-signed and bound to principal/tenant/scope, the queue snapshot
  digest and a 5-minute expiry, so any membership or version change
  invalidates a page cursor. Absent, invisible and other-tenant reads all
  answer the identical `humanwork.not_found` NOT_FOUND envelope.
- Composition wiring through `internal/transport/cell` and
  `internal/transport/edge`; the serve graph gained the
  `work-item-queue-reader` port (golden + conformance updated).
- Wire additions: `WorkItem` gains `proposal_ref`, `claimed_by`,
  `claim_expires_at` and repeated `permitted_actions` (additive, wire-safe;
  `check:apigate` PASS).
